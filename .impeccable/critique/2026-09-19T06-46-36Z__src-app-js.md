**Priority recommendations.**

1. **P2 — Let the background belong to the page.** `LainDataStream` is mounted inside the relatively positioned `HeroContainer`, and its background is absolutely positioned within that section. At a 1440px viewport the background occupies a centered 1160px-wide band and ends at the hero boundary. Move the artwork layer outside that constrained section in a future implementation. Size one stationary layer to the viewport so scrolling does not stretch a landscape image across a very tall document. Reserve visible margin space for the subject, protect reading columns with a dark gradient, and retain opaque or nearly opaque terminal/project surfaces. Use a separately checked mobile crop. Artwork visibility around solid panels is appropriate for the user's chosen treatment. Keep the existing stream local or reduce it; carrying the still artwork across the site does not require expanding motion. Suggested action: `$impeccable layout`.

2. **P2 — Give projects distinct visual evidence.** Both featured cards currently have a domain, a simple architecture strip, a paragraph, tags, and the same link treatment. Use a real inbox crop for temporary mail and a genuine request/response example or more informative architecture illustration for the API gateway. Add one specific engineering decision or lesson per project, based on actual work. A selected reversing/CTF note could later establish the security side when a shareable artifact exists; a large new blog is unnecessary. Suggested action: `$impeccable shape`.

3. **P2 — Make the mixed identity legible and bring the human story forward.** Use the full name and handle together in the first viewport. A possible direction is: “CS graduate from CUHK. I build web services and enjoy taking software apart.” Explain security coursework and past CTF experience in their actual context. Trim repeated `HUMAN OPERATED` / `LOCAL SESSION` / `human behind the shell` framing where it duplicates other explanations. A sentence such as “Cheat Engine got me curious about what programs are doing underneath” communicates personality directly. Preserve the user's informal voice. Suggested action: `$impeccable clarify`.

4. **P2 — Make important small text easier to read.** Numerous technical labels and stickers use approximately 10–11px text, and narrow-screen navigation reaches 10.88px. Raise information that visitors must read toward 12–14px and use miniature type only for optional decoration. Align the Projects and Toolbox heading scales: their current relative sizes change across desktop/mobile. The mobile hero is approximately 1004px tall at 390px width, so reducing repeated shell explanations and excess vertical space would get readers to work sooner. Suggested action: `$impeccable typeset`.

5. **P2 — Correct small factual/control inconsistencies.** The visible introduction says graduate; `whoami` and `about` still say student. The visible and terminal skills lists differ. Confirm the actual skills and keep both presentations consistent. Consider replacing the WIP “35%” with a meaningful milestone if the percentage no longer represents current progress. The background component has no manual pause control despite the design notes describing one; if its ongoing animation remains, add the promised control. Suggested action: `$impeccable harden`.
